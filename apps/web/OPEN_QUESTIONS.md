# apps/web — open questions

Each item states what the code does now (the narrowest safe behaviour) and what needs a decision. Items marked `// OPEN:` in the code point here.

| # | Question | What the code does now | Where |
|---|---|---|---|
| 1 | **Who builds a new workbook's first snapshot?** The contract says `snapshot` is the latest `IWorkbookData`, but not whether `POST /api/workbooks` stores one. | When `GET /api/workbooks/:id` returns `snapshot: null`, the editor builds a blank workbook from `sheets` (one Univer sheet per `SheetMeta`, the spec §7.1 default columns in `headerRow`). The first autosave stores it with the returned `version` as `baseVersion`, so it can never overwrite a snapshot written in the meantime (409). With `snapshot: null` **and** no `sheets`, or a snapshot that is not a workbook, the editor refuses to open and says so. | `src/editor/workbook-data.ts` |
| 2 | **Renaming a workbook.** The phase 1 contract has no rename endpoint. | The title is asked once, in the «ملف جديد» dialog (default «ملف بلا عنوان»). It cannot be changed afterwards. | `src/screens/NewWorkbookDialog.tsx` |
| 3 | **Linked project name.** `WorkbookSummary` carries `bcProjectId` only. Spec §12.1 asks for the linked project. | The files screen shows «مشروع رقم 4021», or «غير مرتبط». Needs the project name in the contract (or a projects endpoint). | `src/screens/FilesScreen.tsx` |
| 4 | **Thmanyah font files.** | `@dawod/thmanyah-font-web` 1.2.0, a community package whose CSS loads the files from jsDelivr (phase 0 choice). Production must self-host the official files once their licence (`font.thmanyah.com/licenses`) is confirmed to allow web embedding (phase 0 report §2.6). | `src/main.tsx` |
| 5 | **Visual identity.** CLAUDE.md §0: what replaces `naf-ui` is open. | A neutral, Google-Sheets-like light theme, defined once in `src/styles/theme.css`; nothing else holds a colour. No dark mode. | `src/styles/theme.css` |
| 6 | **Sign-out.** naf-auth's `POST /auth/logout` (answers `{ ok, next }` to `fetch`) is not in `packages/shared/src/api.ts`. | No sign-out control. Add it to the contract to get one. | — |
| 7 | **`/denied` copy.** naf-auth sends document navigations it refuses to `/denied?r=<reason>`, and leaves the wording to the platform. | A minimal page maps `inactive`, `not_member`, `bad_state`, `auth_failed` to Arabic sentences written here; any other reason gets a generic one. The wording needs approval. A 403 `access_denied` from a `fetch` gets the same sentences. | `src/screens/MessageScreens.tsx`, `src/strings.ts` |
| 8 | **Time zone of «آخر تعديل».** | `YYYY-MM-DD HH:mm`, 24-hour, Latin digits, in the browser's time zone. Should it be fixed to `Asia/Riyadh`? The optional Hijri display (§12.2) is not built. | `src/lib/format.ts` |
| 9 | **Session expiry during unsaved edits.** naf-auth renews tokens server-side, so a 401 means the central session itself ended. | Any 401 sends the browser to the `login` URL (with `next` = the current page). If edits are unsaved, the browser's own "leave page?" prompt is the only guard: leaving loses them. A local draft or a sign-in popup would need a decision. | `src/lib/api.ts`, `src/editor/EditorScreen.tsx` |
| 10 | **Autosave timing.** Spec §6.1's "every 200 operations or 5 minutes idle" describes the server-side snapshots of phase 6 (Durable Object). | Phase 1 PUTs the whole snapshot 1.5 s after the last change, at most 10 s after the first unsaved one. Network, 429 and 5xx failures retry after 2, 5, 15, 30 s (then every 30 s); other failures wait for «إعادة المحاولة». | `src/lib/autosave.ts` |
| 11 | **After a conflict (409).** | Saving stops for good, the grid becomes read-only, and the API's Arabic message is shown with «إعادة تحميل الملف». Reloading shows the stored version; the edits that could not be saved are not kept or merged. Realtime collaboration (phase 6, §17-2) is meant to replace this. | `src/editor/EditorScreen.tsx` |
| 12 | **Leaving the editor.** | In-app navigation saves pending changes on the way out; it asks first (`window.confirm`, whose buttons are in the browser's language) only when a save failed. The browser's Back button cannot be intercepted: failed saves are then lost without asking. | `src/lib/router.tsx`, `src/editor/EditorScreen.tsx` |
| 13 | **Search scope.** | The placeholder says «ابحث بعنوان الملف»; `q` is sent as typed (trimmed). What the API matches is its decision. | `src/screens/FilesScreen.tsx` |
| 14 | **RTL grid layer: redraw after enabling.** Finding for the owners of `@naf-sheets/univer-rtl` (not modified here). | The layer's heartbeat withdraws the mirror unless text is drawn through it within 3 s. In the app the sheet has already painted and then sits idle, so without help the mirror was withdrawn ~3 s after opening every workbook (seen in Chromium; the spike hid it because it kept changing the sheet after enabling). The editor now calls the public `FWorksheet.refreshCanvas()` whenever the layer reports `mirrored: true`. Suggest the layer mark the scene dirty itself after enabling. | `src/editor/univer-host.ts` |
| 15 | **Lifecycle `Steady`.** CLAUDE.md: wait for Steady before mutating. | The app never writes to the model itself, so it does not wait (Steady comes a fixed 3 s after first render in `@univerjs/ui`). It listens for changes from `createWorkbook` on; while loading, Univer ran no mutation on the workbook unit, and the lazy automatic row-height mutation is ignored as a trigger (it still travels with the next real save). The grid is covered until the RTL layer has answered, so the unmirrored grid does not flash. | `src/editor/univer-host.ts`, `src/editor/workbook-data.ts` |
| 16 | **Mobile.** §12.2 asks for a simplified view and edit mode on phones. | Not built. Both screens work at 375 px without horizontal page scroll; the files table scrolls inside its frame and hides three columns. The RTL layer is untested on touch (phase 0 report §9.4). | `src/styles/app.css` |
